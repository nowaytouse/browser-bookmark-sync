# Native Bookmark Cleaner handoff — 2026-10-14

`bookmark-review` is a Rust/egui desktop application, not a web page or WebView. The main window follows one workflow: import, exact deduplication, check/review, then export a new consolidated HTML. There is no navigation sidebar.

## GUI workflow

1. Open **Import HTML** or **Import browsers**. Browser import reads temporary copies and shows browser, Profile, collection, state and raw count. Discovery failures for unrelated or unclassified directories are recorded without aborting readable browsers. Interactive reading-list import keeps successful sources and explicitly reports failed reads; strict CLI export still rejects genuine reading-list read errors. Missing, unsupported, unverified and successfully read empty sources are different states. Failed imports and empty partial imports keep the previously loaded document and decisions. Read issues are visible, partial imports show a limitation count, and failed/unverified source details open automatically.
2. Exact duplicate URLs are initially marked for removal after their first occurrence. These are copy-cleanup decisions, not dead-link verdicts, and can be reset or undone. Uncertain and untested URLs remain retained unless the user explicitly chooses removal.
3. On macOS, **Start check** creates a private fresh batch with its own input, engine and empty database. It uses the existing launchd supervisor, independently of the App and ChatGPT, without an overall deadline. Python 3 is required; the bundled App includes the engine. Settings offer a local HTTP proxy (default `http://127.0.0.1:6152`) or explicit direct routing, and a 5–60 second request timeout. The saved route, timeout and hashed DNS policy are fixed in the new batch and verified again before the worker starts. Existing checks do not read live preferences.
4. **Refresh progress** is manual and displays the last reported batch state, not a fresh process-liveness check. There is no agent progress monitor or automatic polling loop. **Load check results** attaches read-only evidence while preserving review decisions. **Open check batch** reopens a batch after closing the App. Successful process exit is not accepted as complete until the immutable input and all planned site/content targets reconcile with completed database runs.
5. Search title, URL or folder; filter by verdict or decision. Checkbox selection is separate from keep/remove decisions. Select all filtered results includes rows outside the visible viewport, with hidden selections counted. Review evidence in the optional inspector, decide individually or in bulk, and use Undo as needed.
6. **Export HTML** asks for a new destination and confirms retained/removal counts. It publishes new HTML plus a sibling `*.review-audit.json`, refusing to overwrite the input or any existing output. The original HTML and live browser Profiles are untouched.

Settings (`⌘,`) have Appearance, Import, Network, Advanced and About tabs. Appearance provides system/light/dark themes, blue/teal/violet/monochrome accents, system/English/Simplified Chinese language, list density, interface scale, layout proportions, fonts and inspector visibility. Display changes can be previewed; Apply saves the draft and Cancel or Escape discards it, including network edits. Display and non-secret connection preferences are persisted privately; bookmark contents and source paths are not saved in that file. `⌘O`, `⌘S` and `⌘Z` import, export and undo.

The network tab exposes localhost/127.0.0.1 HTTP proxy host and port, explicit direct connections that ignore environment proxies, and per-request timeout. **Check proxy port** is a bounded background TCP-listener check, not an HTTP proxy or internet-health test. The DNS presets are automatic, Cloudflare-first and AliDNS-first. They control encrypted DoH evidence for failed sites; HTTP continues to use its system resolver. Two distinct providers remain required for NXDOMAIN confirmation. Proxy mode disables independent direct DNS probes and explains that the saved preset is only used for future direct checks. These settings never alter OS DNS, proxy software, existing scan files or browser Profiles. Slow mode, concurrency 2, curl confirmation, no target limit and conservative death rules are not adjustable.

## Grouped review and beginner settings

The welcome screen includes **Try sample bookmarks**, backed by `tests/fixtures/native-grouped-review.html`. It reads no browser files. The 20-entry synthetic sample includes two exact duplicate occurrences, nested Unicode folder paths, long/empty titles and non-web URLs. Its network state remains untested. Practice can export 18 retained entries and two duplicate removals without overwriting the synthetic input.

Folder, website and status grouping are display views only. Original occurrence IDs and folder metadata stay unchanged, including duplicate occurrences. Group checkboxes apply to the current filtered IDs, preserve unrelated selection, and display partial selection. Collapsing groups hides rows but does not clear selection or make cleanup decisions. Select/invert/uncertain/clear actions live in one selector menu. Empty searches offer a reset action and explain why no rows are shown. Rows remain virtualized; group models rebuild on filter/group changes, not every frame.

Settings add layout proportions, system/reading fonts, a violet accent, saved default grouping and developer mode. The same shared native theme drives controls, logo and text; no per-screen palette or web font service is introduced. About has a theme-aware bookmark logo, version and source link. Source availability is not represented as an unspecified open-source license.

The DNS backup toggle only affects auxiliary direct DoH evidence. On temporary primary failure, it tries the other distinct provider. Primary NXDOMAIN always requires independent confirmation regardless of the toggle. Security blocks and successful primary responses do not trigger backup queries. Temporary-primary plus one fallback NXDOMAIN does not qualify as two NXDOMAIN observations. Policies, hashes and supervisor validation include the setting.

Developer mode is off by default and affects display only. Raw bookmark ID/verdict/decision tags and footer flags are absent when it is disabled. It does not enable browser writes, relax death rules or run checks automatically. Display/network changes still use draft Apply/Cancel semantics and private atomic settings storage; defaults load for older preference files.

Evidence is read through a read-only SQLite connection; only completed content-check evidence is attached to exact URLs. A manual removal is never represented as a health verdict.

## Known boundaries

- Universal source coverage is not verified: Safari custom Favorites/Profile mappings, independent Safari Technology Preview storage and Gecko reading-list support remain gaps. Successful import of discovered sources or completion of their network check cannot close these gaps.
- Windows/Linux builds and UI have not been accepted. The toolkit is cross-platform, but independent launch and browser collection in this handoff remain macOS-oriented.
- The new GUI scan-start path has regression and mock coverage, but a fresh live network run was intentionally left for the user. Historical evidence is not current network truth.
- Existing-output rejection and dirty-document guards have model tests; they are not claimed as a complete native-dialog acceptance matrix.
