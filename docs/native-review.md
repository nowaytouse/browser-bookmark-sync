# Native Bookmark Cleaner handoff — 2026-10-13

`bookmark-review` is a Rust/egui desktop application, not a web page or WebView. The main window follows one workflow: import, exact deduplication, check/review, then export a new consolidated HTML. There is no navigation sidebar.

## GUI workflow

1. Open **Import HTML** or **Import browsers**. Browser import reads temporary copies and shows browser, Profile, collection, state and raw count. Discovery failures for unrelated or unclassified directories are recorded without aborting readable browsers. Interactive reading-list import keeps successful sources and explicitly reports failed reads; strict CLI export still rejects genuine reading-list read errors. Missing, unsupported, unverified and successfully read empty sources are different states. Failed imports and empty partial imports keep the previously loaded document and decisions. Read issues are visible, partial imports show a limitation count, and failed/unverified source details open automatically.
2. Exact duplicate URLs are initially marked for removal after their first occurrence. These are copy-cleanup decisions, not dead-link verdicts, and can be reset or undone. Uncertain and untested URLs remain retained unless the user explicitly chooses removal.
3. On macOS, **Start check** creates a private fresh batch with its own input, engine and empty database. It uses the existing launchd supervisor, independently of the App and ChatGPT, without an overall deadline. Python 3 is required; the bundled App includes the engine. Settings offer a local HTTP proxy (default `http://127.0.0.1:6152`) or explicit direct routing, and a 5–60 second request timeout. The saved route, timeout and hashed DNS policy are fixed in the new batch and verified again before the worker starts. Existing checks do not read live preferences.
4. **Refresh progress** is manual and displays the last reported batch state, not a fresh process-liveness check. There is no agent progress monitor or automatic polling loop. **Load check results** attaches read-only evidence while preserving review decisions. **Open check batch** reopens a batch after closing the App. Successful process exit is not accepted as complete until the immutable input and all planned site/content targets reconcile with completed database runs.
5. Search title, URL or folder; filter by verdict or decision. Checkbox selection is separate from keep/remove decisions. Select all filtered results includes rows outside the visible viewport, with hidden selections counted. Review evidence in the optional inspector, decide individually or in bulk, and use Undo as needed.
6. **Export HTML** asks for a new destination and confirms retained/removal counts. It publishes new HTML plus a sibling `*.review-audit.json`, refusing to overwrite the input or any existing output. The original HTML and live browser Profiles are untouched.

Settings (`⌘,`) have Appearance, Import & evidence, Network & checks and About tabs. Appearance provides system/light/dark themes, blue/teal/monochrome accents, system/English/Simplified Chinese language, list density, interface scale and inspector visibility. Display changes can be previewed; Apply saves the draft and Cancel or Escape discards it, including network edits. Display and non-secret connection preferences are persisted privately; bookmark contents and source paths are not saved in that file. `⌘O`, `⌘S` and `⌘Z` import, export and undo.

The network tab exposes localhost/127.0.0.1 HTTP proxy host and port, explicit direct connections that ignore environment proxies, and per-request timeout. **Check proxy port** is a bounded background TCP-listener check, not an HTTP proxy or internet-health test. The DNS presets are automatic, Cloudflare-first and AliDNS-first. They control encrypted DoH evidence for failed sites; HTTP continues to use its system resolver. Two distinct providers remain required for NXDOMAIN confirmation. Proxy mode disables independent direct DNS probes and explains that the saved preset is only used for future direct checks. These settings never alter OS DNS, proxy software, existing scan files or browser Profiles. Slow mode, concurrency 2, curl confirmation, no target limit and conservative death rules are not adjustable.

## Safety and verification

The export model verifies input hashes, retained anchors, folder headings, metadata and order before publishing. Private output uses Unix permissions 0600 and no-clobber publication. Evidence is read through a read-only SQLite connection; only completed content-check evidence is attached to exact URLs. A manual removal is never represented as a health verdict.

The current validation covers 446 tests across 11 suites, 8 launcher mock tests, formatting, and all-target Clippy with warnings denied. Cargo reports two existing unused-dependency diagnostics (`rayon`, `html5ever`); compilation and Clippy exit successfully. Regression cases include duplicate occurrences, Unicode folders, metadata, stale input, invalid decisions, output/audit collisions, private permissions, source-state semantics, immutable batch input, complete target coverage and evidence reload preserving decisions. Network regressions cover old preference-file compatibility, invalid saves preserving the prior file, all DNS presets with distinct confirmation providers, immutable DNS snapshot validation, worker failure before a changed policy can start, direct requests ignoring inherited environment proxies, explicit proxies remaining effective, IPv4/IPv6 localhost port checks, and asynchronous port-check results not clearing another operation's busy state. Proxy route tests use isolated child processes and loopback fixtures only. Import regressions include inaccessible unrelated directories, readable nested browsers beside inaccessible vendor children, genuine denied browsers remaining reported, successful reading lists surviving another failed source, and failed retries preserving existing state.

Native macOS UI acceptance exercised settings/theme/language previews, search, filtered selection, bulk removal, Undo, inspector and native-dialog export. The five-entry fixture exported four retained links and one exact-duplicate removal, retaining uncertain/non-web links and metadata. The original tracked fixture stayed unchanged. Evidence is under ignored `target/native-gui-20261010/test-evidence/`.

The 2026-10-13 network-settings acceptance used the rebuilt signed App. Actual native controls verified disabled DNS presets in proxy mode and enabled presets in direct mode, port 0 blocking Apply, timeout and DNS draft edits, Escape/Cancel restoring proxy port 6152 and timeout 10, and a background local-port check showing TCP reachability without claiming HTTP/internet success. English/light and Chinese/dark previews were inspected at the existing 1.3 interface scale. The final build keeps validation errors outside the scroll area, immediately above the fixed footer. The pre-existing preferences file hash remained unchanged; no settings were applied to the user's file, no browser import was repeated, and no scan was launched. Web-oriented design-state scripts inspected zero Rust controls; their output is not native accessibility or WCAG acceptance. Full VoiceOver and cross-platform acceptance remain unverified.

The shipped automatic-import defect was reproduced through the actual GUI: an inaccessible `Application Support/discord` directory caused total import failure. After the fix, the rebuilt App's **Import browsers** action completed on the same machine: 117,620 raw records, 93,860 exact duplicate occurrences marked for removal, and 23,760 retained in the export preview. The UI displayed 67 source rows and 30 read issues/coverage limitations, including genuine browser permission denials. These are snapshot import/review counts, not completed network checks or executed export removals. No permissions were granted, browser Profiles modified, or network scan started during this acceptance.

The delivered App is a development build with local ad-hoc signing, not a notarized release. Its bundled engine is verified against the build output. A new real network scan was not started during this GUI handoff; the user controls subsequent runs from the App. The earlier `clean-20261001-aMMCpA` batch is historical evidence, not a current running task.

## Known boundaries

- Universal source coverage is not verified: Safari custom Favorites/Profile mappings, independent Safari Technology Preview storage and Gecko reading-list support remain gaps. Successful import of discovered sources or completion of their network check cannot close these gaps.
- Windows/Linux builds and UI have not been accepted. The toolkit is cross-platform, but independent launch and browser collection in this handoff remain macOS-oriented.
- The new GUI scan-start path has regression and mock coverage, but a fresh live network run was intentionally left for the user. Historical evidence is not current network truth.
- Existing-output rejection and dirty-document guards have model tests; they are not claimed as a complete native-dialog acceptance matrix.
